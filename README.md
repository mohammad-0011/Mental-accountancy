# Mental-accountancy
An accounting system with Persian language support and an excellent user interface.

# سیستم حسابداری Mental — نسخهٔ تخصصی صنف باتری‌فروشان

نرم‌افزار حسابداری رومیزی (ویندوز) با نشان و لوگوی **Mental** — دفتر فروش، انبار،
حساب اشخاص، چک‌ها و امور مالی، همراه با ماژول اختصاصی
**باتری فرسوده (ضایعات)، سریال و گارانتی باتری**.

رابط کاربری کاملاً فارسی و راست‌به‌چپ است و همهٔ تاریخ‌ها شمسی (جلالی) هستند.
تمام اطلاعات روی همین رایانه و در پایگاه‌دادهٔ محلی SQLite نگهداری می‌شود.

## ۱) اجرای برنامه

### الف) فایل نصب (اینستالر) — ساده‌ترین راه
```
dist\installer\HesabDari-Saba-Setup.exe        ← برای مشتری (یک فایل، همین را بفرستید)
dist\installer\HesabDari-Saba-Admin-Setup.exe  ← برای رایانهٔ خودتان (نسخهٔ فروشنده)
```
با دوبار کلیک، ویزارد نصب فارسی باز می‌شود و این‌ها را **خود کاربر انتخاب می‌کند**:

1. **مسیر نصب** برنامه
2. **پوشهٔ اطلاعات** (پایگاه‌داده و فایل لایسنس) — جدا از محل نصب، تا هنگام
   نصب نسخهٔ تازه یا حذف برنامه از دست نرود
3. **پوشهٔ پشتیبان‌ها** — جدا از پوشهٔ اطلاعات؛ همهٔ پشتیبان‌های دستی و خودکار
   همان‌جا می‌نشینند و از داخل برنامه مدیریت می‌شوند
4. **نشانی سرور لایسنس** (اختیاری) برای فعال‌سازی آنلاین
5. **توکن مدیر** (فقط برای نصب نسخهٔ فروشنده) — همان مقدار `SABA_ADMIN_TOKEN`
   روی سرور؛ با آن، درخواست‌های لایسنس از داخل برنامه تأیید/رد می‌شوند.
6. گزینه‌های میان‌بر دسکتاپ، منوی شروع، اجرای خودکار پس از نصب

نصب‌کننده چند فایل کوچک کنار برنامه می‌گذارد (`data-dir.txt`، `backup-dir.txt`،
`license-server.txt`، `client-token.txt`، `admin-token.txt`) و برنامه هنگام اجرا
همان‌ها را می‌خواند. یک **حذف‌کننده** هم ساخته می‌شود که در «برنامه‌ها و
ویژگی‌ها»ی ویندوز ثبت است و داده‌ها و پشتیبان‌ها را پاک نمی‌کند.

نصب بی‌صدا (برای چند رایانه یا آزمون):
```
HesabDari-Saba-Setup.exe --silent --dir="C:\HesabDari" ^
    --data-dir="D:\HesabData" --backup-dir="D:\HesabBackup" ^
    --server=https://license.example.com --no-run

HesabDari-Saba-Admin-Setup.exe --silent --dir="C:\HesabDari-Admin" ^
    --server=https://license.example.com --token=CLIENT-TOKEN ^
    --admin-token=ADMIN-TOKEN --no-desktop --no-run
HesabDari-Saba-Setup.exe --uninstall --silent --keep-data
```

> ویندوز می‌تواند هنگام اجرا هشدار SmartScreen بدهد (فایل امضای تجاری ندارد)؛
> «More info → Run anyway» کافی است. برای امضای رسمی باید گواهی Code Signing خرید.

### ب) فایل اجرایی بدون نصب
```
dist\HesabDari-Saba.exe           ← نسخهٔ مشتری (نیازمند لایسنس)
dist\HesabDari-Saba-Admin.exe     ← نسخهٔ فروشنده (صدور و مدیریت لایسنس)
```
کار می‌کند؛ در این حالت اگر پوشهٔ داده انتخاب نشده باشد، `data\` کنار فایل
اجرایی ساخته می‌شود. پنجرهٔ برنامه به‌صورت یک پنجرهٔ مستقل باز می‌شود (از موتور
Microsoft Edge یا Chrome که روی ویندوز نصب است استفاده می‌کند).

در نخستین اجرای نسخهٔ مشتری، صفحهٔ **فعال‌سازی** باز می‌شود (بخش ۲ را ببینید).

**کاربر پیش‌فرض:** `admin` — **گذرواژه:** `admin`

**نشانی ثابت برنامه:** `http://127.0.0.1:8756`

> اگر برنامه از قبل در حال اجرا باشد، دوبار کلیک روی فایل اجرایی همان نمونهٔ در
> حال اجرا را تشخیص می‌دهد و فقط پنجره را باز می‌کند (نمونهٔ دوم ساخته نمی‌شود).

#### اگر پیام «ارتباط با سرویس برنامه برقرار نشد» دیدید
یعنی پنجرهٔ مرورگر باز است ولی سرویس داخلی برنامه پاسخ نمی‌دهد. ترتیب رفع مشکل:

1. روی دکمهٔ **تلاش دوباره** بزنید. برنامه هر چند ثانیه خودش بررسی می‌کند و
   به‌محض برگشتن سرویس، **خودکار** وصل می‌شود؛ لازم نیست کاری بکنید.
2. فایل اجرایی را یک‌بار دیگر اجرا کنید؛ سرویس روی همان نشانی `8756` بالا می‌آید.
3. اگر باز هم نشد: در «Task Manager» همهٔ نمونه‌های `HesabDari-Saba.exe` را ببندید
   و برنامه را دوباره اجرا کنید.
4. برای عیب‌یابی: فایل گزارش `data\app.log` کنار فایل اجرایی را ببینید؛ هر اجرا و
   پورت انتخابی در آن ثبت می‌شود.

> صفحه و دارایی‌های برنامه با `no-store` سرو می‌شوند تا مرورگر هیچ‌وقت صفحهٔ کهنهٔ
> یک سرویس مرده را نشان ندهد.

### ج) اجرای مستقیم از سورس (برای توسعه)
```
run.bat
```
یا:
```
python run.py
```
برای اجرای صفحهٔ مدیر از سورس: متغیر محیطی `SABA_MODE=admin` را تنظیم کنید.

### د) ساخت مجدد فایل‌های اجرایی و نصب‌کننده
```
python build.py                          # ساخت هر دو برنامه (کاربری + مدیر)
python build.py --user                   # فقط نسخهٔ کاربری
python build.py --admin                  # فقط نسخهٔ مدیر
python build.py --installer               # exeها + فایل نصب مشتری
python build.py --installer-admin         # + فایل نصب نسخهٔ مدیر
python build.py --installer-only          # فقط فایل نصب، از exeهای موجود در dist
python build.py --user --installer --server=https://license.example.com
```
`--server=` نشانی سرور لایسنس را داخل فایل نصب می‌گذارد تا هنگام نصب پیشنهاد شود.
خروجی‌ها در `dist` و `dist\installer` ساخته می‌شوند. پایان ساخت، **بازرسی امنیتی
خودکار** انجام می‌شود: اگر کلید خصوصی اشتباهاً داخل نسخهٔ کاربری رفته باشد، ساخت
ناموفق اعلام می‌شود.

> محل ذخیرهٔ اطلاعات: در نصب با اینستالر، همان پوشه‌ای که کاربر انتخاب کرده است
> (`data-dir.txt` کنار فایل اجرایی)؛ در اجرای بدون نصب، پوشهٔ `data\` کنار فایل
> اجرایی. برای انتقال دستی برنامه، پوشهٔ داده را هم همراه ببرید.

## ۲) دو نسخهٔ برنامه و سیستم لایسنس

### الف) دو فایل اجرایی

| فایل | برای چه کسی | تفاوت اصلی |
|------|-------------|------------|
| `dist\HesabDari-Saba.exe` | مشتری | بدون لایسنس معتبر هیچ داده‌ای باز نمی‌شود؛ **کلید خصوصی صدور لایسنس داخل آن نیست** |
| `dist\HesabDari-Saba-Admin.exe` | فروشنده | صدور و مدیریت لایسنس، مدیریت کامل کاربران؛ کلید خصوصی فقط داخل همین نسخه است |

هر دو از یک کد ساخته می‌شوند؛ تفاوت آن‌ها (۱) وجود کلید خصوصی و (۲) حالت اجرا
است که از نام فایل اجرایی (`...-Admin.exe`) تشخیص داده می‌شود.

### ب) فعال‌سازی آنلاین — روش پیشنهادی

سرور لایسنس و بات بله در پروژهٔ کنار همین پوشه هستند:
[`../bot-hesab-dari`](../bot-hesab-dari/README.md). جریان کار:

1. مشتری برنامه را اجرا می‌کند؛ صفحهٔ **فعال‌سازی** باز می‌شود (نه صفحهٔ ورود).
2. در کارت «فعال‌سازی آنلاین»، نام فروشگاه، شمارهٔ تماس و اگر لازم بود
   **توضیح (نوت) برای فروشنده** را می‌نویسد و **ارسال درخواست فعال‌سازی به
   فروشنده** را می‌زند (یا فقط کد رایانه را در بات بله برای شما می‌فرستد).
3. درخواست **هم‌زمان به بات بله و به برنامهٔ فروشنده** می‌رود؛ هر کدام را
   راحت‌تر دیدید همان‌جا تأیید کنید:
   - **در برنامه:** «حساب کاربری و لایسنس» → «وضعیت لایسنس» → کارت
     «درخواست‌های لایسنس» → **تأیید** → انتخاب **تعداد کاربر** و **تعداد روز**
     (ویا «بدون انقضا») و یک توضیح اختیاری، سپس «تأیید و صدور لایسنس».
   - **در بات بله:** «✅ تأیید» → نسخه (پایه/پرمیوم) → مدت
     (۳۰/۹۰/۱۸۰/۳۶۵ روز یا بدون انقضا) → تعداد کاربران.
4. لایسنس امضاشده برای همان دستگاه صادر می‌شود. برنامهٔ مشتری هر ۵ ثانیه خودش
   بررسی می‌کند و **خودکار فعال می‌شود** (نیازی به فرستادن فایل نیست).

پنل تأیید در برنامه فقط در **نسخهٔ فروشنده** باز می‌شود و به `admin-token.txt`
(توکن مدیر) نیاز دارد که اینستالر نوشته است. نشانی سرور لایسنس و کلیدها
هنگام نصب تنظیم می‌شوند و **در رابط کاربری نمایش داده نمی‌شوند** (بخش
تنظیمات سرور از برنامه برداشته شده است).

**تمدید و درخواست تازه:** مشتریِ فعال می‌تواند از «حساب کاربری و لایسنس» دوباره
درخواست بفرستد (مثلاً برای کاربر بیشتر یا تمدید) و همان مسیر تأیید را طی کند.

**لغو از راه دور:** با `/revoke <شناسهٔ لایسنس>` در بات، لایسنس باطل می‌شود و
برنامهٔ مشتری در نخستین بررسی اینترنتی قفل می‌شود. بررسی خودکار طبق
`license_check_hours` (پیش‌فرض هر ۶ ساعت) انجام می‌شود و اگر مشتری بیش از
`GRACE_DAYS` روز (پیش‌فرض ۱۵) به اینترنت وصل نشود، برنامه تا نخستین بررسی قفل
می‌ماند.

> لایسنس‌های آنلاین در بدنهٔ امضاشدهٔ خود نشان `online` دارند؛ **لایسنس‌های دستی
> قدیمی هیچ‌وقت به اینترنت نیاز ندارند** و مثل قبل کار می‌کنند.

### ج) فعال‌سازی دستی (بدون اینترنت / بدون سرور)

1. مشتری برنامه را اجرا می‌کند؛ کد رایانهٔ مثل `DE50-D8C7-814F-60F7-BFD1` روی صفحه
   نوشته شده است. مشتری همان کد را برای شما می‌فرستد.
2. شما در `HesabDari-Saba-Admin.exe` → بخش **لایسنس و فعال‌سازی** → **صدور لایسنس**،
   نام مشتری، نسخه، تعداد کاربران، مدت اعتبار، کد دستگاه و قابلیت‌ها را وارد می‌کنید.
3. برنامه یک متن لایسنس و یک فایل `...key` می‌دهد. آن را به مشتری می‌دهید.
4. مشتری آن را در بخش «وارد کردن دستی متن لایسنس» صفحهٔ فعال‌سازی می‌گذارد و
   **فعال‌سازی برنامه** را می‌زند.

> پس از فعال‌سازی، فایل `license.key` در پوشهٔ داده ساخته می‌شود.
> برای دیدن دوبارهٔ صفحهٔ فعال‌سازی (مثلاً برای آزمون)، همان فایل را حذف کنید.

### د) ساخت کلیدهای ریشه (فقط یک‌بار، نزد فروشنده)

کلیدهای لایسنس **از قبل در `app/license_keys` ساخته شده‌اند**. اگر بخواهید
از صفر بسازید (و می‌دانید چه می‌کنید):

```
python tools/make_license_keys.py
```

| فایل | نوع | بسته‌بندی می‌شود در |
|------|-----|----------------------|
| `app/license_keys/root_private.key` | **محرمانه — هرگز به مشتری ندهید** | فقط `...-Admin.exe` |
| `app/license_keys/root_public.key` | عمومی | هر دو برنامه |

> ⚠️ اگر کلید خصوصی را پاک کنید یا با `--force` بسازید، **همهٔ لایسنس‌های
> قبلی باطل می‌شوند** و باید دوباره لایسنس صادر و برنامهٔ مشتری روزآمد شود.
> از `root_private.key` نسخهٔ پشتیبان محرمانه نگه دارید.

### هـ) چه چیزی تضمین شده است؟ (صادقانه)

هیچ برنامهٔ آفلاینی «کرک‌ناپذیر مطلق» نیست: کسی که فایل اجرایی را روی سیستم خودش
دارد می‌تواند با تلاش کافی چک را دور بزند. اما این موارد تضمین می‌شود:

- **ساختن لایسنس جعلی ناممکن است.** امضای دیجیتال Ed25519 نامتقارن است؛ کلید
  خصوصی هیچ‌وقت در نسخهٔ مشتری نیست. حتی با داشتن کل سورس برنامهٔ مشتری،
  تولید لایسنس معتبر ممکن نیست.
- **کپی/دست‌کاری لایسنس بی‌فایده است.** هر تغییر یک نویسه در متن لایسنس،
  امضا را باطل می‌کند. لایسنس مقید به دستگاه، روی رایانهٔ دیگر کار نمی‌کند.
- **تاریخ و نسخه قابل عقب‌بردن نیست** (لایسنس منقضی رد می‌شود و عقب بردن ساعت
  سیستم تشخیص داده می‌شود).
- **کوکی نشست قابل جعل نیست:** کلید امضای نشست برای هر نصب تصادفی ساخته می‌شود
  (هیچ کلید ثابتی در کد نیست) و پس از ۵ تلاش ناموفق، ورود هر کاربر موقتاً قفل می‌شود.
- **کلید خصوصی در نسخهٔ کاربری نیست** — و `build.py` خودش بعد از هر ساخت این را
  بازرسی می‌کند.

### و) قابلیت‌های نسخهٔ پرمیوم

| قابلیت | بخش‌های برنامه |
|--------|----------------|
| چند انبار | انبارها، انتقال بین انبار، اصلاح موجودی |
| بیش از یک کاربر فعال | افزودن کاربر دوم و بیشتر (سقف کاربران از لایسنس می‌آید) |
| پشتیبان‌گیری، بازیابی و خروجی CSV | پشتیبان‌گیری، خروجی اکسل |
| گزارش‌های مالی پیشرفته | تراز آزمایشی، سود و زیان، ترازنامه |
| ردیابی و گردش فعالیت | گردش فعالیت کاربران، گزارش اصلاح و حذف |

بخش‌های پرمیوم در نسخهٔ پایه با نشان «پرمیوم» نشانه‌گذاری می‌شوند و سرور هم آن‌ها
را با خطای ۴۰۲ رد می‌کند (یعنی قفل فقط ظاهری نیست).

### ز) کاربران، نقش‌ها و دسترسی‌ها

- **مدیر سیستم:** دسترسی کامل، صدور لایسنس، مدیریت کاربران، تنظیمات.
- **کاربر عادی:** فقط بخش‌های مجاز. برای هر کاربر می‌توانید هر یک از این‌ها را
  جداگانه روشن/خاموش کنید: فاکتور فروش و خرید، صنف باتری، انبارداری، حسابداری،
  چک و اسناد، تعاریف پایه، گزارشات.
- هر کاربر نام کامل، تلفن، ایمیل، یادداشت، وضعیت فعال/غیرفعال و **آخرین ورود** دارد.
- مدیر می‌تواند کاربر را غیرفعال، قفل موقت ورودش را باز، یا گذرواژه‌اش را بازنشانی کند.
- کاربر پیش‌فرض نخستین نصب `admin` با گذرواژهٔ `admin` است؛ **همان ابتدا آن را
  تغییر دهید** (تنظیمات → تغییر گذرواژه من).

## ۳) امکانات برنامه

### الف) تعاریف پایه
- ثبت اشخاص و طرف حساب‌ها (کد اختصاصی، کد ملی، کد اقتصادی، تلفن، نشانی، مانده اول دوره، سقف اعتبار)
- ثبت کالا با کد، بارکد، گروه، واحد سنجش، قیمت خرید، قیمت فروش تک‌فروشی و عمده، حد سفارش (آلارم موجودی)
- مشخصات تخصصی باتری: برند، آمپر، نوع (خودرو / یو‌پی‌اس / موتور)، ظرفیت، مدت گارانتی
- گروه کالا، واحد سنجش، چند انبار

### ب) خرید و فروش
- فاکتور فروش، پیش‌فاکتور، برگشت از فروش
- فاکتور خرید، برگشت از خرید
- تخفیف ردیفی و تخفیف کل فاکتور، مالیات بر ارزش افزوده (قابل تنظیم)
- پرداخت نقدی / کارت / چک / نسیه در هر فاکتور
- ثبت سریال و مدت گارانتی در هر قلم باتری
- حذف و اصلاح فاکتور با برگشت خودکار اثرات انبار و اسناد
- ثبت خودکار سند حسابداری برای هر فاکتور

### ج) انبارداری
- موجودی تعدادی و ریالی، ارزش موجودی انبار
- کاردکس (گردش کالا) با ماندهٔ تجمعی
- انتقال بین انبارها
- افزایش/کاهش دستی موجودی با سند خودکار
- آلارم کالاهای زیر حد سفارش در داشبورد

### د) حسابداری
- دریافت و پرداخت وجه
- سند حسابداری دستی با کنترل تراز
- تراز آزمایشی، صورت سود و زیان، ترازنامه
- دفتر ریز حساب اشخاص (بدهکار/بستانکار)
- گزارش اسناد و ردیابی اصلاح و حذف

### هـ) چک و اسناد
- چک‌های دریافتنی و پرداختنی
- وضعیت چک: نزد ما / خرج‌شده / به حساب گذاشته / پاس‌شده / برگشتی
- چک ضمانتی
- گزارش سررسید چک‌ها با آلارم

### و) ماژول اختصاصی باتری
- **سریال و گارانتی باتری:** ثبت خودکار سریال هنگام فروش، محاسبهٔ تاریخ پایان گارانتی،
  گزارش گارانتی‌های فعال و منقضی
- **مرجوعی گارانتی:** ثبت مرجوعی باتری معیوب
- **باتری فرسوده / ضایعات:** خرید باتری فرسوده از مشتری بر اساس تعداد/وزن/قیمت هر کیلوگرم،
  با امکان نقدی یا نسیه
- **انبار ضایعات:** موجودی تعداد و وزن و ارزش، با کسر خودکار در فروش
- **فروش ضایعات:** فروش به بازیافت با کنترل موجودی
- **تبدیل باتری مرجوعی به ضایعات** با یک کلیک

### ز) سیستم
- کاربران و سطوح دسترسی، تغییر گذرواژه
- گردش فعالیت کاربران (ورود/خروج و عملیات)
- گزارش اصلاح و حذف (Audit Trail)
- یادداشت و یادآور با آلارم ابتدای برنامه
- **پشتیبان‌گیری مدیریت‌شده:** انتخاب پوشهٔ پشتیبان از داخل برنامه، پشتیبان خودکار
  هنگام باز شدن برنامه، ساخت پشتیبان فوری، بازگردانی هر نسخه با یک کلیک (قبلش
  خودکار یک نسخهٔ امن از وضعیت فعلی گرفته می‌شود)، حذف و دانلود نسخه‌ها، و تعیین
  تعداد نسخه‌های نگه‌داشته‌شده (پیش‌فرض ۲۰)
- بازیابی از فایل بیرونی، خروجی CSV برای اکسل
- تنظیمات فروشگاه، واحد پول، نرخ مالیات، شروع سال مالی، انبار پیش‌فرض ضایعات

## ۴) طراحی رابط کاربری

رابط کاربری بر اساس سیستم طراحی تولیدشده توسط اسکیل
[ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) بازنویسی شده است:

| بخش | مقدار |
|------|-------|
| نام برنامه | **سیستم حسابداری Mental** (نشان و لوگو: `web/logo.svg`) |
| سبک | Minimalism & Swiss Style (شبکه‌ای، پرکنتراست، بدون تزئین) |
| رنگ اصلی | سرمه‌ای `#1E3A5F` |
| رنگ دوم | آبی `#2563EB` |
| رنگ تأکید (مثبت) | سبز `#047857` |
| هشدار / خطا | `#DC2626` |
| پس‌زمینه / متن | `#F8FAFC` / `#0F172A` |
| تم تیره | `#0B1220` پس‌زمینه / کارت `#141C2B` |
| فونت | Vazirmatn (به‌صورت محلی و آفلاین) |

نکات پیاده‌شدهٔ چک‌لیست اسکیل:

- **بدون ایموجی به‌عنوان آیکون** — ۶۲ آیکون خطی SVG از Lucide (`web/icons.svg`)
- حلقهٔ فوکوس دیدنی روی همهٔ عناصر تعاملی (`:focus-visible`)
- کنتراست متن حداقل ۴.۵:۱ (سبز `#059669` فقط برای پرکردن، برای متن `#047857`)
- احترام به `prefers-reduced-motion`
- واکنش‌گرا در ۳۷۵ / ۷۶۸ / ۱۰۲۴ / ۱۴۴۰ (منوی کشویی، ریل آیکونی، تمام‌عرض)
- حالت خالی راهنما‌دار، اسکلتون هنگام بارگذاری، پیام‌های `aria-live`
- مودال دسترس‌پذیر: `role=dialog`، بستن با `Esc`، قفل فوکوس، بازگشت فوکوس
- پالت جستجوی سراسری با `Ctrl+K`
- اعداد با ارقام هم‌عرض و چینش LTR در جدول‌ها
- **تم روشن/تیره**: کلید گوشهٔ پایین هر صفحه (`#themeToggle`)؛ انتخاب کاربر در
  `localStorage` می‌ماند و بار نخست از تنظیم سیستم‌عامل خوانده می‌شود.
  هر دو تم از یک مجموعه توکن رنگ (`--bg`, `--card`, `--fg`…) می‌آیند.
- **نشان و لوگو**: نشان «Mental» (مربع گرد آبی/سرمه‌ای با حرف M و خط سبز) در
  صفحهٔ ورود، فعال‌سازی، نوار کناری، فاوآیکون و آیکون فایل اجرایی ویندوز.
  ساخت آیکون: `python tools/make_icon.py` → `assets/app.ico`
  (فایل برداری: `web/logo.svg`، نسخهٔ معکوس برای نوار تیره: `web/logo-inverse.svg`).
- **انیمیشن‌های ملایم**: ورود پله‌ای کارت‌ها و ردیف‌های جدول، باز/بسته شدن
  مودال‌ها و پیام‌ها، چرخش آیکون کلیدها، جان‌گرفتن لوگو، و گذار نوار کناری —
  همه با `prefers-reduced-motion` خاموش می‌شوند و با کلید «انیمیشن» پایین صفحه
  (`#animToggle`) دوباره روشن می‌شوند (انتخاب کاربر در `localStorage` می‌ماند).
- **صدای برنامه**: پیام موفق/خطا، باز و بسته شدن پنجره‌ها و کلیک منو با
  Web Audio (بدون فایل صوتی بیرونی) ساخته می‌شود؛ کلید «صدا» پایین صفحه
  (`#soundToggle`) آن‌ها را خاموش/روشن می‌کند و انتخاب کاربر ذخیره می‌شود.

> فایل وردی `web/fonts/Vazirmatn-*.woff2` و اسپرایت `web/icons.svg` همراه برنامه
> بسته‌بندی می‌شوند و برنامه کاملاً آفلاین کار می‌کند.

## ۶) نکات
- پایگاه‌داده محلی است؛ برای چند کاربر همزمان روی شبکه، برنامه باید روی یک سیستم
  میزبان اجرا شود. (نسخهٔ سازمانی برای این کار قابل توسعه است.)
- برای صحت محاسبات، قبل از هر ماه از اطلاعات پشتیبان بگیرید (بخش «پشتیبان‌گیری»).
- ماژول پیامک (SMS) و اتصال به بارکدخوان/کارت‌خوان در این نسخه پیاده‌سازی نشده است.
- **لغو لایسنس از راه دور** فعال است (از طریق بات بله و سرور لایسنس)؛
  سقف تعداد **دستگاه** هر مشتری هم در بات قابل تعیین است. لایسنس‌های دستی قدیمی
  همچنان آفلاین و بدون نیاز به اینترنت کار می‌کنند.
- سرور لایسنس و بات بله در پوشهٔ کنار همین پروژه‌اند
  ([`../bot-hesab-dari`](../bot-hesab-dari/README.md)) و برای اجرا به یک سرویس
  همیشه‌روشن (VPS یا میزبان کانتینری مثل justrunmy.app) نیاز دارند.
