# سرور لایسنس آنلاین سیستم حسابداری Mental + بات بله

این پوشه، سرور لایسنس سیستم حسابداری Mental است: یک سرویس کوچک پایتونی که
هم **API برای برنامهٔ مشتری** دارد و هم **بات پیام‌رسان بله** را اجرا می‌کند.
همهٔ لایسنس‌ها فقط از راه بات شما صادر و لغو می‌شوند و کلید خصوصی صدور
لایسنس **فقط روی این سرور** است، نه روی رایانهٔ مشتری.

```
مشتری (برنامهٔ ویندوزی)  ──HTTPS──▶  این سرور  ──بات بله──▶  شما (فروشنده)
        ▲                                  │
        └──── لایسنس امضاشده (Ed25519) ────┘
```

---

## ۱) چه چیزی اینجا هست

| فایل | کار |
|---|---|
| `app.py` | سرویس Flask: API برنامهٔ مشتری + راه‌اندازی نخِ بات |
| `botlogic.py` | منطق بات: درخواست‌ها، تأیید با دکمه، صدور، لغو، گزارش‌ها |
| `bale.py` | کلاینت سبک API بله (فقط کتابخانهٔ استاندارد) |
| `store.py` | پایگاه‌دادهٔ SQLite: مشتریان، دستگاه‌ها، درخواست‌ها، لایسنس‌ها |
| `config.py` | خواندن تنظیمات از متغیرهای محیطی / فایل `.env` |
| `sabalic/` | هستهٔ لایسنس؛ **کپی بایت‌به‌بایت** `app/licensing.py` برنامه |
| `keys/root_private.key` | کلید خصوصی امضای لایسنس ← **محرمانه، هرگز به مشتری ندهید** |
| `keys/root_public.key` | کلید عمومی (همین کلید داخل برنامهٔ مشتری است) |
| `tests/test_bot.py` | ۴۶ بررسی سرتاسری (بدون نیاز به شبکه) |

## ۲) اجرای محلی (برای آزمایش روی رایانهٔ خودتان)

```bash
cd bot
pip install -r requirements.txt         # flask + cryptography
python app.py                           # http://127.0.0.1:5000
python tests/test_bot.py                # اجرای آزمون‌ها
```

اگر می‌خواهید بات به بله وصل نشود (فقط API):
`SABA_BOT_DISABLE=1 python app.py`

## ۳) راه‌اندازی در بله (یک‌بار)

1. توکن بات را در `BALE_BOT_TOKEN` بگذارید (در فایل `.env` یا در پنل میزبان).
2. به بات خودتان در بله پیام `/whoami` بدهید. عددی که جواب می‌دهد شناسهٔ
   گفت‌وگوی شماست.
3. همان عدد را در `ADMIN_CHAT_IDS` بگذارید (چند شناسه را با کاما جدا کنید).
   **تنها این شناسه‌ها می‌توانند لایسنس صادر یا لغو کنند.**
4. سرور را اجرا/استقرار دهید. با `/help` فهرست دستورها را می‌بینید.

## ۴) استقرار روی justrunmy.app

میزبان یک اپ کانتینری می‌سازد؛ ساده‌ترین راه، بارگذاری ZIP همین پوشه است:

1. کل این پوشه را ZIP کنید (بدون `__pycache__` و `data/*.db`).
2. در پنل justrunmy.app زبان **Python** را انتخاب و ZIP را بارگذاری کنید.
3. **Environment Variables** را پر کنید (همان‌ها که در `.env.example` هست):

   | نام | مقدار |
   |---|---|
   | `BALE_BOT_TOKEN` | توکن بات بله |
   | `ADMIN_CHAT_IDS` | شناسهٔ گفت‌وگوی شما در بله |
   | `GRACE_DAYS` | مثلاً `15` |
   | `PUBLIC_URL` | نشانی همین سرویس پس از استقرار |
   | `SABA_ADMIN_TOKEN` | توکن مدیر (برای تأیید درخواست‌ها از داخل برنامه) |

   کلید خصوصی دو راه دارد: فایل `keys/root_private.key` داخل ZIP (ساده‌تر)
   یا متغیر `SABA_ROOT_PRIVATE_KEY` با همان محتوای base64 (کمی امن‌تر، چون
   داخل فایل‌های پروژه نمی‌ماند).

4. فرمان اجرا: اگر پنل فرمان می‌خواهد، همین را بگذارید:
   ```
   gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 120 app:app
   ```
   یا ساده‌تر `python app.py` (پورت را از `PORT` می‌خواند).
5. پس از استقرار، نشانی سرویس را باز کنید؛ باید صفحهٔ «✅ سرور لایسنس
   سیستم حسابداری Mental» را ببینید و در `GET /health` پاسخ `{"ok": true}` بگیرید.
6. همان نشانی را هنگام ساخت اینستالر بدهید (فیلد «نشانی سرور لایسنس») تا
   برای همهٔ مشتریان تنظیم شود. برای نسخهٔ فروشنده، مقدار `SABA_ADMIN_TOKEN`
   را هم در فیلد «توکن مدیر» همان اینستالر بگذارید تا پنل تأیید درخواست‌ها
   در برنامه باز شود.

**ساخت اینستالر مشتری با نشانی همین سرور** (در پوشهٔ پروژهٔ برنامه):

```bash
cd ..
python build.py --user --installer --server=https://<نشانی سرویس شما>
# خروجی: dist/installer/Mental accounting Setup.exe
```

از آن پس، کاربر لازم نیست چیزی تنظیم کند: اینستالر نشانی سرور را
(`license-server.txt`) کنار برنامه می‌گذارد و صفحهٔ فعال‌سازی درخواست آنلاین
می‌فرستد. کاربر می‌تواند فقط کد رایانه را هم در همین بات بفرستد.

> نکته: سرویس برای اینکه مشتری‌ها به آن وصل شوند به **پورت عمومی** نیاز دارد.
> میزبان‌های کانتینری این کار را خودشان انجام می‌دهند؛ روی VPS خودتان، پشت
> یک دامنه/آی‌پی با HTTPS قرارش دهید (نخِ بات به پورت کاری ندارد).

## ۵) API برنامهٔ مشتری

| نشانی | کار |
|---|---|
| `GET /health` | بررسی زنده‌بودن سرویس |
| `GET /api/v1/info` | نسخه، مهلت بی‌اتصال، تاریخ سرور |
| `POST /api/v1/request` | ثبت درخواست فعال‌سازی (اثر انگشت، نام، تلفن، **توضیح/نوت**) |
| `GET /api/v1/status` | وضعیت همین دستگاه؛ اگر تأیید شده باشد متن لایسنس |
| `POST /api/v1/checkin` | بررسی دوره‌ای برای تشخیص **لغو از راه دور** |

پاسخ‌ها `status` یکی از این‌هاست: `none`, `pending`, `active`, `denied`,
`revoked`, `expired`.

### API پنل فروشنده (برنامهٔ دسکتاپ)

برنامهٔ فروشنده با **توکن مدیر** (`SABA_ADMIN_TOKEN`) از همین دو نشانی استفاده
می‌کند؛ نتیجه در سرور با تأیید از بات بله یکی می‌شود:

| نشانی | کار |
|---|---|
| `GET /api/v1/admin/requests` | درخواست‌های در انتظار + گزینه‌های روز/تعداد کاربر + پیش‌فرض‌ها |
| `POST /api/v1/admin/decide` | تأیید یا رد یک درخواست |

بدنهٔ تأیید:

```json
{"request_id": 12, "action": "approve", "edition": "premium",
 "seats": 5, "days": 180, "note": "توضیح اختیاری مدیر"}
```

* `seats`: تعداد کاربر مجاز. `days`: مدت به **روز** (صفر = بدون انقضا).
* `action` می‌تواند `deny` باشد؛ آن وقت `seats`/`days` لازم نیست.
* سرآیند لازم: `X-Saba-Admin: <SABA_ADMIN_TOKEN>`.
* اگر `SABA_ADMIN_TOKEN` روی سرور تنظیم نشده باشد، این در **از برنامه بسته**
  است (۴۰۳) و تأیید فقط از بات انجام می‌شود — پس هیچ نصبِ مشتری‌ای
  نمی‌تواند خودش را تأیید کند.
* نتیجهٔ تصمیم در سرور ثبت می‌شود (`decided_via = app|bot` و `decided_note`).

امنیت این نشانی‌ها:

* لایسنس برگشتی با **Ed25519** امضا شده و به **اثر انگشت همان دستگاه** قید
  است؛ روی رایانهٔ دیگر کار نمی‌کند و دست‌کاری‌اش آن را باطل می‌کند.
* اثر انگشت (۶۴ نویسهٔ هگز) یا کد کوتاه (۲۰ نویسه) خودش نقش رمز را دارد؛
  بدون آن کسی نمی‌تواند لایسنس کسی را بخواند.
* محدودیت نرخ درخواست (`RATE_LIMIT_PER_HOUR`) برای جلوگیری از حملهٔ ساده.
* در صورت تمایل `CLIENT_TOKEN` را هم پر کنید؛ آن وقت برنامه باید همان را در
  سرآیند `X-Saba-Client` بفرستد (دروازهٔ نرم، نه مرز امنیتی).

## ۶) دستورهای بات

**فروشنده (شما):**

| دستور | کار |
|---|---|
| `/inbox` | درخواست‌های در انتظار، هر کدام با دکمهٔ «✅ تأیید» و «❌ رد» |
| `/req 12` | جزئیات یک درخواست |
| `/customers` | فهرست مشتریان |
| `/customer 3` | جزئیات مشتری و دستگاه‌هایش |
| `/devices` | دستگاه‌های ثبت‌شده |
| `/licenses` | لایسنس‌های صادرشده |
| `/revoke SB-140507-0003` | لغو لایسنس (برنامهٔ مشتری قفل می‌شود) |
| `/add نام | تلفن` | افزودن مشتری دستی |
| `/limit 3 2` | سقف تعداد دستگاه‌های مجاز مشتری |
| `/msg 3 متن` | پیام به مشتری |
| `/stats` | آمار سرور |
| `/server` | وضعیت تنظیمات سرور |

**مشتری:** `/activate` (ثبت درخواست)، `/status`، `/key`، `/help`.
مشتری می‌تواند فقط کد ۲۰ نویسه‌ای را از روی صفحهٔ برنامه بفرستد و بقیه
خودکار است.

**جریان تأیید:** درخواست می‌آید → «✅ تأیید» → نسخه (پایه/پرمیوم) →
**مدت به روز** (۳۰/۹۰/۱۸۰/۳۶۵ یا بدون انقضا) → تعداد کاربران → لایسنس صادر و
هم به شما و هم به مشتری داده می‌شود. برنامهٔ مشتری خودش (هر ۵ ثانیه) بررسی
می‌کند و فعال می‌شود؛ نیازی به فرستادن فایل نیست.

همین کار از داخل **برنامهٔ فروشنده** هم انجام می‌شود: «حساب کاربری و لایسنس» →
«وضعیت لایسنس» → کارت «درخواست‌های لایسنس» → تأیید با انتخاب تعداد کاربر و
تعداد روز. درخواست‌های مشتری شامل **توضیح (نوت)** خودش هم هست.

## ۷) امنیت — صادقانه

* **ساختن لایسنس جعلی ناممکن است:** امضای Ed25519 و کلید خصوصی فقط اینجاست.
  حتی کسی که سورس کامل برنامهٔ مشتری را داشته باشد نمی‌تواند لایسنس بسازد.
* **لغو از راه دور کار می‌کند** تا وقتی برنامه به اینترنت وصل شود: دورهٔ
  بررسی (پیش‌فرض روزی یک‌بار + هنگام باز شدن) و مهلت بی‌اتصال
  (`GRACE_DAYS`). بعد از تمام‌شدن مهلت، برنامه قفل می‌شود.
* **هیچ برنامه‌ای «کرک‌ناپذیر مطلق» نیست.** کسی که فایل اجرایی را روی
  سیستم خودش دارد، با تلاش کافی می‌تواند چک را دور بزند. کاری که این طرح
  تضمین می‌کند: ساخت لایسنس، کپی لایسنس، دست‌کاری لایسنس و استفادهٔ
  طولانی بدون اجازهٔ شما ناممکن/بی‌فایده است.
* **توکن مدیر** (`SABA_ADMIN_TOKEN`) مثل توکن بات محرمانه است و فقط روی
  رایانهٔ فروشنده (در `admin-token.txt`) می‌نشیند؛ هرگز در بستهٔ مشتری نیست.
* **توکن بات، کلید خصوصی و `.env` را جایی منتشر نکنید.** اگر توکن لو رفت،
  در بله توکن را Revoke کنید و مقدار تازه بگذارید. اگر کلید خصوصی لو رفت،
  باید کلید تازه بسازید و **هر دو برنامه** را از نو بسازید (همهٔ لایسنس‌های
  قبلی باطل می‌شوند).

## ۸) آزمون‌ها

```bash
python tests/test_bot.py
```

بررسی می‌کند: یکسانی هستهٔ لایسنس با پروژهٔ برنامه، سازگاری متقابل امضا/تأیید،
جریان کامل درخواست→تأیید→صدور→فعال‌سازی، لغو از راه دور، رد لایسنس
دست‌کاری‌شده، رد دستگاه دیگر، محافظت نقش مدیر، محدودیت نرخ و گفت‌وگوی مشتری.
